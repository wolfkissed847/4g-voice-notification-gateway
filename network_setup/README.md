# Network Architecture — LAN only (ตัดการสลับไป 4G data อัตโนมัติออกแล้ว)

## แนวคิด

Raspberry Pi ในโปรเจคนี้ใช้ **อินเทอร์เน็ตจาก LAN ออฟฟิศเท่านั้น** (dashboard, gTTS API, NTP ฯลฯ)
**ไม่มี auto-failover ไปใช้ data ของโมดูล 4G เมื่อ LAN หลุด** — เดิมออกแบบไว้ให้สลับอัตโนมัติผ่าน
NetworkManager แต่ตัดออกแล้ว เพราะ**ยังไม่ได้ verify ว่าโมดูล A7670C คุยสาย (voice call) พร้อมกับใช้ 4G
data ได้จริงหรือไม่** (ขึ้นกับว่าเป็น VoLTE ที่ทำพร้อมกันได้ หรือ CSFB ที่สลับโหมดตอนคุยสายจน data หลุด)
ความเสี่ยงคือถ้าไม่รองรับ การพึ่ง 4G เป็นทั้งช่องโทรและช่อง internet fallback อาจชนกันเองพอดีตอนไฟดับ
ซึ่งเป็นจังหวะที่แย่ที่สุดที่จะเกิดปัญหา — ตัดทิ้งไว้ก่อนจนกว่าจะมีฮาร์ดแวร์จริงมาทดสอบ

**สิ่งสำคัญที่ต้องแยกให้ชัด:**

| ช่องทาง | ใช้ทำอะไร | ขึ้นกับ LAN ไหม |
|---|---|---|
| เสียง (โทรออกแจ้งเตือน) | AT command (`ATD`) ผ่านซิมโดยตรง | **ไม่ขึ้นกับ LAN/อินเทอร์เน็ตเลย** — ใช้สัญญาณเสียงของซิมเสมอ ไม่ว่า LAN จะล่มหรือไม่ |
| อินเทอร์เน็ต | Dashboard, เรียก gTTS API, NTP sync | ขึ้นกับ LAN **เท่านั้น** — ถ้า LAN ล่ม (เช่นตอนไฟดับที่ router/switch ออฟฟิศดับไปด้วย) ส่วนนี้ใช้ไม่ได้ชั่วคราว |

ดังนั้นถ้า LAN ล่ม dashboard เข้าไม่ได้ และ**การโทรแจ้งเตือนก็ทำไม่ได้ด้วย** — เดิมตั้งใจให้ audio cache
ช่วยกันไว้ (ถ้าข้อความเคย generate เสียงมาก่อนจะเล่นได้แม้ไม่มีเน็ต) แต่ตัดสินใจเลิก cache แล้ว
(6 ส.ค. 2569 — เพราะวัดเวลาจริงแล้ว gTTS ใช้เวลาแค่ ~0.3-0.9 วิ/ข้อความ ซึ่งน้อยมากเมื่อเทียบกับ
เวลาอัปโหลดไฟล์เสียงเข้าโมดูล GSM ที่กินเวลาเป็นสิบวิ จึงไม่คุ้มความซับซ้อนของการดูแล cache)
**ผลคือตอนนี้ทุกสายที่โทรออกต้องมีอินเทอร์เน็ตเสมอ ไม่มีทางเลี่ยงแล้ว**

> **เรื่องไฟเลี้ยง (ตัดสินใจแล้ว 6 ส.ค. 2569):** ระบบนี้**ไม่มีไฟสำรอง** (UPS/power bank) — Pi กับโมดูล 4G
> ใช้ไฟ AC ออฟฟิศเส้นเดียวกับอุปกรณ์อื่น ไฟดับคือระบบดับทั้งหมด ไฟกลับมาแล้ว container ขึ้นเองอัตโนมัติ
> (`restart: unless-stopped`) ระบบจึงครอบคลุมเฉพาะเหตุที่เกิดขณะยังมีไฟและ LAN ปกติ เป็นการยอมรับ
> ขอบเขตโดยตั้งใจ ไม่ใช่ข้อบกพร่องที่ลืมแก้

## วิธีติดตั้ง

1. เชื่อมต่อโมดูล A7670C เข้ากับ Pi (ผ่าน USB ตามที่ตั้งค่าไว้ใน `.env`) — ใช้สำหรับโทรออกอย่างเดียว
   ไม่ต้องตั้งค่าอะไรเพิ่มฝั่ง network
2. ต่อ Pi เข้า LAN สายแลนออฟฟิศตามปกติ (DHCP หรือ static ตามที่ IT ออฟฟิศกำหนด) — ไม่ต้องรัน script ใดๆ
   เพิ่มเติมสำหรับหัวข้อนี้

## ข้อจำกัดที่ควรรู้ (ต้อง verify กับฮาร์ดแวร์จริง)

- **LAN ล่ม = โทรแจ้งเตือนไม่ได้เลย**: ไม่มี audio cache กันไว้แล้ว (ดูด้านบน) gTTS ต้องต่อเน็ตทุกครั้ง
  ที่จะโทร ถ้า LAN ล่มพร้อมกับเหตุการณ์ที่ต้องแจ้ง (เช่นไฟดับที่ router/switch ออฟฟิศดับไปด้วย) ระบบ
  จะสร้างเสียงไม่ได้และแจ้งเตือนไม่ได้ — ถือเป็นข้อจำกัดที่ยอมรับแล้วโดยตั้งใจ
- **ถ้าในอนาคตอยากกลับไปทำ 4G-internet-fallback**: ต้องทดสอบกับฮาร์ดแวร์จริงก่อนว่าโมดูลคุยสาย+ใช้ data
  พร้อมกันได้ไหม (เช็คจาก AT command manual ของ A7670C ว่ารองรับ VoLTE หรือแค่ CSFB) ถ้ารองรับจริง
  มี script ตั้งค่า NetworkManager priority ไว้แล้วที่ [`setup_network_failover.sh`](./setup_network_failover.sh)
  (ยังไม่ได้ใช้งานในดีไซน์ปัจจุบัน เก็บไว้เป็นจุดเริ่มต้นเผื่อกลับมาทำต่อ)
